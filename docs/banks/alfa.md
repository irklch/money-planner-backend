# Альфа-Банк: правила импорта (первая версия)

Адаптер: `app/modules/imports/parsing/alfa.py`. Образец: `tests/fixtures/banks/alfa/alfa_statement_test.xlsx`, тестовая обезличенная копия. Тесты: `tests/test_bank_alfa.py`, правила проверяются тестами `test_rule_*`.

Решения подтверждены 2026-10-04.

## Ограничения

- Поддерживается только `.xlsx` «Выписка по счету» в проверенной раскладке колонок.
- Поддерживаются только **рублёвые** счета: в шапке должно быть явно указано `Валюта счета` RUR/RUB. Если поля нет, оно пустое или валюта другая, выписка получает существующий `422 unknown_bank`, API не меняется.
- CSV и другие варианты Excel-выписки Альфа-Банка **не поддерживаются**, пока для них нет образца.

## Распознавание

Выписка распознаётся, только если выполнены все условия:
- в одной строке есть заголовки «Дата операции», «Дата проводки», «Код», «Категория», «Описание», «Сумма в валюте счета», «Статус»;
- над ними стоят «Выписка по счету» и «Операции по счету»;
- в документе есть подпись АО «АЛЬФА-БАНК».

Колонки ищутся по тексту заголовка, номер строки не важен. Объединённые ячейки, переносы строк и неразрывные пробелы учитываются.

Значение поля шапки («Валюта счета», «Клиент») берётся из ячейки рядом с подписью — не дальше трёх колонок правее. Поэтому пустое поле не подхватывает текст правого блока шапки («Расходы», «На дату формирования выписки»).

## Правила

| # | Правило |
|---|---|
| 1 | Дата расхода — **дата операции**, календарная. Дата проводки нужна только для проверки завершённости. Аномалии дат в синтетическом образце (проводка раньше операции) правилом реальной выписки не считаются. |
| 2 | Исходящие **переводы физлицам по СБП** («Перевод по СБП … на …») остаются расходами на проверку пользователю: это может быть оплата услуг или покупок. **СБП C2B** («Исходящий платеж QR по СБП C2B») — покупка. Исключаются только явно определённые переводы между своими счетами. |
| 3 | Положительные операции пропускаются как поступления. Возвраты не угадываются и расходы не уменьшают. Поддержка возвратов отложена до отдельного контракта и реального образца. |
| 4 | **Переводы между своими счетами** («Внутрибанковский перевод между счетами, <ФИО клиента из шапки>. Со счёта … на счёт …») исключаются в обе стороны. Входящие не входят в `skippedIncomeCount`: счётчик учитывает только остальные пропущенные поступления. Перевод считается своим, только если ФИО в описании совпадает с полем «Клиент» из шапки. Если поля нет, оно пустое или ФИО другое, перевод остаётся обычной операцией: списание — расход на проверку, поступление — в `skippedIncomeCount`. |
| 5 | Проведённой считается операция со статусом «Выполнен» или с пустым статусом при заполненной дате проводки. Остальные статусы, а также повреждённые дата или сумма дают `partially_read`, такие строки операциями не становятся. Новые значения статусов добавляются только после получения образца. |
| 6 | Только рублёвые счета, валюта указана явно (см. «Ограничения»). |
| 7 | Колонка «Категория» банка — тип операции («Прочие операции», «Финансовые операции»). Как категория расходов она не используется. Категоризация идёт по очищенному и маскированному описанию и категориям приложения, результат проверяет пользователь. |

Суммы читаются через `Decimal`, с запятой и пробелами между разрядами, включая неразрывные. Служебные строки не становятся операциями: шапка, итоги банка, подпись, «Страница N из M», повтор заголовка.
